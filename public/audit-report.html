Executive Summary

The April 9 training guide accurately describes the core project lifecycle (intake → pending → ready → production → receiving → complete) and the basic role split (Taylor / Drake / Receiver / Jon). The phase auto-advance model, the 3-gate blanks checklist, and the QuickBooks payment flow are still correct.

However, six weeks of build work has significantly extended OpsHub. The guide is missing two entire departments (Ecomm and the Distro split into Receiving/Shipping/Fulfillment as separate surfaces), two major new modules (Art Studio, Pre-order workflow), one new architectural layer (multi-tenant for IHM), and roughly 12 page-level features that have shipped since.

Bottom line: the guide is structurally sound but materially incomplete. Recommend a full rewrite organized by department (matching the sidebar), keeping the workflow narrative as a cross-cutting section.

Recommendations

1. Full rewrite, organized by department
The April 9 guide was organized by workflow stage (Builder → Costing → Quote → ...). With three departments now (Labs / Distro / Ecomm) plus Contacts, the cleaner mental model is department-first — matching the sidebar — then page-by-page within each. Keep a "Project workflow start-to-finish" cross-cutting section as the narrative spine, but make it reference the department pages by name.
2. Per-role docs as companion artifacts
Five per-role HTML docs (Taylor / Drake / Abigail / Warehouse / Manager) deliver the same content from a different angle. Each only covers what that role touches day-to-day. New hires skim their role doc; the training guide is the reference. Both live in /references.
3. SOPs stay separate
The Pre-order SOP already exists as its own doc — referenced from /references. Future SOPs (e.g. Customer Service playbook for Abigail, Decorator Onboarding) should follow the same pattern: one HTML file per SOP, linked from References. Training guide gives the overview; SOPs give the deep workflow.
4. Update cadence
Set a quarterly review: every three months, do this same audit. New features that ship between audits get a one-line note in the version log at the top of the training guide. Stale content gets fixed in place. This keeps drift bounded.
