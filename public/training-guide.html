System Overview

What is OpsHub?
OpsHub is the internal platform that runs every project from intake through delivery. It also runs the e-commerce side — pre-orders, in-stock drops, and always-on stores — under one roof.

Multi-tenant. OpsHub serves two companies — House Party Distro (HPD) and IHM. Each has its own subdomain, clients, decorators, and payment provider. The active company is shown as a small tenant slug under the sidebar logo.

Auto-advancing phases. Projects flow through stages automatically. You never set the phase manually — the system reads what's been done and moves the project along.

Project Workflow — End to End

The full path of a project
  1. Create Project Taylor
    Projects → + New Project. Pick client (or create one). Set shipping route + ship date. Lands you on Product Builder.
  2. Add Items Taylor
    Product Builder tab. Use the S&S catalog or other suppliers. Enter sizes + quantities. Set blank vendor / SKU per item.
  3. Brief the Art Taylor
    Art Studio. Upload client art. Send the brief to a designer. Designer uploads WIP / final files. Client reviews and approves on their portal.
  4. Cost the Items Drake
    Costing tab. Pick a decorator, define print locations, set margin. Click "Lock In Pricing" when done.
  5. Send Quote Drake
    Quote tab. Preview, send to client via email. They get a portal link to review & approve.
  6. Send Proofs & Invoice Drake
    Proofs & Invoice tab. Generate proofs, create the invoice (QB for HPD, Stripe for IHM), send to client.
  7. Order Blanks & Send PO Drake
    Blanks tab — enter S&S order #s & costs. PO tab — set ship date, ship-to, fill notes, send PO to decorator.
  8. Track Production Drake
    Production page (or Production tab in-project). When decorator ships, enter tracking + Mark Shipped. Notify client.
  9. Receive at HPD Warehouse
    Receiving page. Confirm per-size quantities, log any variance or damage, upload packing slip photos.
  10. Ship to Client Warehouse
    Ship-through: Shipping page → enter outbound tracking → ship. Stage: enter into Shopify (Abigail) → fulfill from ShipStation. Drop-ship: decorator ships direct, project completes on production-page tracking.
Phases advance automatically. You never manually change a project's phase. Do your work on each tab, the system figures out where the project is.

Navigation & Layout

Left rail — department switcher
The left rail is a fixed icon column with one button per department:
Labs — projects, art, production Distro — receiving, shipping, fulfillment Ecomm — pre-orders, drops Contacts — clients, decorators, designers Refs — training docs (lightbulb icon) Settings — team management
Each user only sees the departments they have access to. The Refs lightbulb is always visible to everyone.

Tenant slug appears in tiny text under the logo (HPD or IHM) so you always know which company you're working in.
Top bar — department pages
The top horizontal nav shows the pages inside the active department. Click any link to navigate within the department. The Cross-link button (e.g. "Distro →") jumps you to the other side of the house quickly.

On the far right: global search (Cmd+K) and your signed-in identifier.
Inside a project
Projects have a horizontal tab strip across the top: Overview · Product Builder · Costing · Quote · Proofs & Invoice · Blanks · PO · Production · Warehouse · Approvals. Color-coded by completion (green done, amber in progress, gray not started). Click any tab to jump.

Core Concepts

Shipping Routes
Set on the Overview tab during project setup. Determines what happens after production.
RouteMeaning
Drop shipDecorator ships direct to client. Never touches HPD.
Ship throughDecorator → HPD → out the door same week. Warehouse confirms qty, ships.
StageDecorator → HPD → held as inventory. Front office enters into Shopify, ships from ShipStation as orders come in.
Per-item override New — individual items can override the job route if a mixed shipment is needed. Set on the Production tab.
Client ETA New
Each item has an optional Client ETA — the date you tell the client they'll receive their goods. Independent from internal vendor ship dates.

Where to set it: Production tab, Production page, Project Overview, or the Client Worksheet (any of these — they all edit the same field).

Where it shows: Client portal item tiles, list view, and detail modal — with a live countdown (red overdue, amber within 3 days, etc.). Blank ETAs fall back to the project's target ship date for display.

Add a one-line note when you change it ("freight delay, rebooked for 5/22") — the note appears on the client portal alongside the date.
Auto-save Everywhere
Costing inputs, item names, notes, sizes, quantities, shipping fields, ETAs — they all auto-save. No save button. A red error toast appears at the bottom right if something failed; otherwise assume saved.

Labs — Dashboard /dashboard Everyone

Command center for active work
The Dashboard surfaces every action that needs attention across all active projects.

KPI strip at top — Active Projects · Items · Units · Prints. Tenant-aware.
Alert buckets grouped by phase — Sales, Proofs, Production, Receiving, Fulfillment. Each card is a clickable command that opens the right tab.
New client onboarding alerts when a client was created but has no project yet.
Activity feed showing recent events across all projects.
Alert color coding
ColorMeaning
RedCritical — overdue, quote rejected, proof revision requested
AmberHigh — invoice action, stalled at decorator (7+ days)
PurpleMedium — send quote, early stall warning (3-6 days)
GrayInfo — awaiting client, ship date missing
2-day follow-up rule: When OpsHub is waiting on a client (quote sent, proofs sent, invoice sent), alerts auto-escalate to amber after 2 days with no response.

Labs — Projects List /jobs Everyone

All projects in one filterable list. Each row shows the project's status bucket distribution — e.g. "Production · 4, Receiving · 2" — so you can see at a glance where a multi-vendor job sits.

Filters: Active / Complete / Cancelled / On Hold. Search by project title or client name.
Sort: Ship date (default), created date, priority.
ASAP sentinel — projects flagged ASAP sort to the top regardless of the date.

Labs — Project Detail /jobs/[id]

Ten tabs, one project
Every project has the same ten-tab strip. Click any tab to switch. The Progress Checklist at top shows which steps are done (green), in progress (amber), or not started (gray).

Overview Tab

Top-line view of the project — phase, ship date countdown, invoice status, costing summary, contacts, items.

Items list — worksheet-style row per item with name, qty, status, and an editable Client ETA input. Edits sync everywhere.
Client swap — change the client on a project. Reassigns contacts, address, and payment terms.
Activity panel — chronological feed of everything that's happened on this project.
Actions: Duplicate · Place on Hold · Delete · Copy Portal Link.

Product Builder Tab Taylor

Add items via the S&S catalog picker (or AS Colour, LA Apparel, Other). Pick supplier → style → color → sizes.
Per-item fields: name (header), garment type, blank vendor/SKU (click bar to change), per-size quantities, notes.
Sizes — Tab / arrow keys move between fields. Dist button auto-distributes a total quantity across sizes using a curve.
Letter designators (A, B, C…) reflect sort_order — consistent across all tabs even if a tab filters items.
Drag to reorder via the ⠿ handle.

Costing Tab Drake

Two panels per item:
• Blanks (left) — supplier, fleece toggle, per-size cost breakdown, item financial summary.
• Decoration (right) — decorator picker, print locations with screens & colors, tag print, finishing & packaging, setup fees, specialty, custom costs.

Print locations — up to 6 locations per item (front, back, sleeves, etc.). Mark a location shared if multiple items use the same screen — combines qty for the rate tier and charges screens once.
Margin tier — pick 10 / 15 / 20 / 25 / 30%. Drives the sell price. Override per-item with the "override" link next to the sell price.
Request Pricing (RFQ) — opens a dialog to email the decorator for an estimate when their pricing isn't in the system.
Lock In Pricing — finalizes costing, turns the step green, unlocks the Quote tab. To make changes, click Unlock Pricing.

Quote Tab Drake

Renders the quote PDF preview with items, sizes, pricing, totals, tax. Send Quote emails it to the client with a portal link.

Client approval — they hit "Approve" on the portal. The quote tab updates with "Approved on [date]".
Client rejection — they leave rejection notes which surface on the Quote tab. You'll also see a red Dashboard alert.

Proofs & Invoice Tab Drake

One tab handles both proofs and invoicing.

Top — Proofs: Item file list with stages (client art → vector → mockup → proof → print ready). Generate proof PDFs. Send to client. Track approval status per item.
Bottom — Invoice: Create QuickBooks invoice (HPD) or Stripe invoice (IHM). Preview PDF. Send invoice with payment link to client. Track payment records.

Art Brief panel links this project to its Art Studio brief.
Variance review — if shipped quantities differ from quoted, a modal flags the stale invoice and lets you push an update.

Blanks Tab Drake

Enter the S&S order # and total cost per item. Three gates check at the top:

✓ Quote approved
✓ Payment received (or N/A for net terms)
✓ All proofs approved

All three must be green before blanks can be ordered.

Bulk apply — select multiple items and apply a single total cost, distributed proportionally.
S&S sync — auto-fills order data from connected S&S account.

PO Tab Drake

POs are grouped per decorator (an accordion per vendor). For each vendor:

Ship date — calendar picker, or ASAP sentinel.
Ship-to address override — defaults to HPD warehouse. Override per vendor (e.g. drop-ship → client address; event drop → venue).
Per-item fields: production files link, incoming goods notes, production notes, packing notes. Use "Copy to all" for shared values.
Send PO — opens email dialog with all decorator contacts checked by default. PO PDF attaches automatically.
UPS account: UPS PO orders automatically use shipping account W28Y51. No manual entry needed.

Production Tab Drake

Per-item tracking + Mark Shipped.

Client ETA + Note at the top of each item — what the client sees on their portal.
Shipping from Decorator section — tracking number + per-size shipped quantities.
Mark Shipped button — flips the item to shipped, locks in ship_qtys, logs activity, sets the decorator assignment to shipped.

Once shipped, the banner shows whether the client was notified (drop-ship only) with a Resend option. For ship-through / stage routes, notification is held until the warehouse receives + ships.

Warehouse Tab

Mostly superseded by the standalone Distro pages (Receiving / Shipping / Fulfillment). Still shows variance alerts for items where received qty < ordered qty.

Approvals Tab New

Bulk proof generation across the entire project. Generate All iterates through items with eligible mockups and creates proofs. Progress tracker shows X of N generated.

Per-item approval status visible at a glance (all approved / pending / revisions requested).

Distro — Receiving /receiving Warehouse

Shipment-grouped intake
Items are grouped by physical shipment — by (decorator, tracking number). The unit of work is the box, not the project.

Tabs:
• Pending — shipments in transit, awaiting receipt
• Received — completed receives, time-bucketed (Today / This week / Last 30 / Older). Plus pinned sections: "Live in Shopify — shelve" (48h window for stage items entered into Shopify) and "Needs attention" (variances or action required).
• Outside — ad-hoc third-party shipments. Can be linked to a job after the fact.
Receive Modal
Click any pending shipment → opens a modal with all items in that box.

For each item:
• Per-size received quantity input (defaults to shipped qty)
• Per-size sample quantity (pulled for QA / photoshoot / client comp)
• Condition selector (good / damaged / other)
• Notes field

Upload packing slips and receiving photos. Existing files appear in a carousel.

Mark Received commits the shipment. Variances against ordered qty flag automatically.
Silent Mode toggle — top-right of the page. Suppresses the automatic "production complete" client email. Use this for backfilling old receives where you don't want to spam the client.

Distro — Shipping /shipping Warehouse

Dispatch outbound for ship-through projects.

Tabs:
• Ready to Ship — projects fully received at HPD, awaiting outbound
• Shipped — completed shipments (audit history, last 30 days, with Older collapsed)

Click a row to open the Ship modal: project header, ship-to + contact, per-item checkboxes (default all selected), outbound tracking input, Mark Shipped button.

Mark Shipped opens the Notify Recipient dialog (unless silent mode is on) — pick which client contact to email and confirm. Client gets the outbound tracking automatically.

Distro — Fulfillment /fulfillment Warehouse New

Read-only chronological intake feed for stage-route shipments over the last 30 days.

Each row = one shipment with its Shopify-entry status:
Green — all items entered in Shopify (warehouse can shelf) Amber — partial Faint — pending front-office entry
Click any row for a read-only detail modal — item breakdown by entry status, received timestamp, tracking, totals.

This is a visibility surface, not an action surface. Shopify entry happens on /ecomm Intake.

Ecomm — Dashboard /ecomm Abigail

Three e-commerce modes, one hub
OpsHub handles three e-comm patterns:

• Pre-orders — open for a window, close, push to production, fulfill
• In-stock drops — pre-made inventory, sells until out
• Always-on stores — continuous webstores with replenishment cycles

Tabs:
• Intake — shipments awaiting Shopify entry (stage route only). Multi-select + bulk "Mark Entered in Shopify".
• Pre-orders — pre-order project list with status workflow
• In-stock drops — drop projects
• Always-on stores — continuous stores

+ New Ecomm Project creates a new fulfillment_project with the chosen mode and platform.

Push-to-Production Wizard
When the pre-order closes, click Push to Production. The wizard:
1. Shows each product with per-size inputs for sold quantities (from Shopify report)
2. Applies the buffer % (default 5-7%) per variant — calculates total ordered qty
3. Shows the grand total
4. On confirm, creates a new Labs job with shipping_route="stage", pre-fills items + buy_sheet_lines, links back to the pre-order

The new Labs job opens in a new tab — Drake picks it up from there.
See the Pre-order SOP (linked from /references) for the full step-by-step playbook including roles, lifecycle dates, and edge cases.

Portals — Client / Vendor / Designer

Client Portal

Each client gets a unique portal link (toggle in client detail). They use it to:
• View their quote with full detail (sizes, pricing, totals)
• Approve or reject quotes (with notes)
• Review and approve proofs in a fullscreen viewer
• Pay via QB or Stripe payment link
• View invoice PDF
• See item ETAs with live countdowns
• Browse all their projects in one shared sidebar (multi-project clients see everything in one place)

Vendor Portal

Each decorator has a unique portal link (from /decorators). They use it to:
• View all active POs with full detail
• See item details, decoration specs, quantities, ship-to address
• Confirm PO receipt
• Report issues
• Enter tracking when items ship

Active POs in a sidebar list, sorted by ship date. Completed orders in a separate tab.

Designer Portal New

Each designer has a unique portal link (from /settings/designers). They use it to:
• See art briefs assigned to them
• Upload WIP files and final art
• Chat per-file with HPD and the client
• Track brief states (WIP Review → Client Review → Revisions → Final Approved)

The portal mirrors the Art Studio modal layout — designers work in the same interface HPD uses.

Payments — QuickBooks & Stripe

Two payment providers by tenant
TenantProviderInvoice flow
HPDQuickBooksOpsHub creates QB invoice → QB generates payment link → client pays via QB
IHMStripeOpsHub creates Stripe invoice → Stripe payment link → client pays via Stripe
The Proofs & Invoice tab forks its UI based on the tenant. New jobs may also let you pick the provider at creation time.
Payment recording
Automatic: When a client pays via the payment link, the provider's webhook fires → OpsHub records the payment, updates the project, fires team notifications, and updates the dashboard.

Manual: If a payment doesn't auto-register, the Payments section on the Proofs & Invoice tab lets you record one by hand (type, amount, invoice #).

Variance review: If the shipped qty differs from the quoted qty after invoicing, a Variance modal flags the stale invoice and lets you push an updated one to the provider.
